# Project kickoff

Use for a new project or material scope uncertainty. Reuse the supplied packet; open 00_System/Project_Kickoff_Prompt.md only when its setup guidance is needed.

Establish outcome, constraints, boundary/owner, acceptance, verification, unknowns and next permitted action. Ask the decision-changing blocker first; batch independent questions. Reuse the approved format.

Auth, state, migration or security risk needs relevant principles and stronger checks. Continue authorized local work; pause only the dependent action needing clarification or new permission before its destructive/live effect.

Research/review-only scopes remain read-only. A recommendation grants no implementation authority. Vault changes require their own scope.
